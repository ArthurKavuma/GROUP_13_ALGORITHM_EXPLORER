Why Limit Naive Recursion to n ≤ 30?

Naive recursion recomputes overlapping subproblems (fib(n-2) is computed twice, fib(n-3) three times, etc.). Its call count grows exponentially as T(n) = 2·F(n+1) − 1 = O(2ⁿ). At n = 30 it makes 2,692,537 recursive calls; at n = 50 it would exceed 40 billion calls and freeze the system. Memoization and Bottom-Up DP store each subproblem once, reducing time to O(n).

              The "False Full" Problem & Circular Solution

              In a Linear Queue, front and rear only move rightward. Once rear == capacity - 1, the queue reports full even if earlier dequeue() calls freed slots 0 .. front-1! The Circular Queue solves this using modulo arithmetic: rear = (rear + 1) % capacity, wrapping rear around to index 0.

                Theoretical vs Experimental Discussion

                • Insertion Sort on Sorted Input: Runs in O(n) time (n − 1 comparisons, 0 shifts) because every element is already ≥ its predecessor.
                • First-Element Quicksort on Sorted Input: Degrades to O(n²) because the pivot A[lo] is always the smallest (or largest) element, creating unbalanced 0 and n − 1 partitions.
                • Randomised Pivot Fix: Swapping a random element into A[lo] prevents sorted/reverse-sorted inputs from consistently producing worst-case splits, restoring O(n log n) expected time.
